# XIRASM 0.3.2

SPIR-V modules may now name their result IDs instead of numbering them by hand, and a
rejected SPIR-V line is reported on the line that caused it.

## SPIR-V result IDs may be names

A SPIR-V instruction may write its result ID as a name:

```asm
spv.use()

OpCapability Shader
OpMemoryModel Logical GLSL450
OpEntryPoint GLCompute %main "main"
OpExecutionMode %main LocalSize 1 1 1
%void = OpTypeVoid
%fn_type = OpTypeFunction %void
%main = OpFunction %void None %fn_type
%entry = OpLabel
OpReturn
OpFunctionEnd
```

A name is accepted everywhere a numeric ID is: as the result ID before `=`, and in every
operand that refers to an ID. A name may contain letters, digits, and the underscore, and
may not begin with a digit.

Numbering follows two rules:

- a numeric ID keeps the number it was written with, so a module that already writes
  numbers assembles to the bytes it always did;
- a name is numbered from 1 upward in the order of its first appearance in the module,
  skipping the numbers that numeric IDs already use.

Numbering a name from where it first appears is what makes a forward reference natural.
`OpEntryPoint` may name the entry point before the `OpFunction` line that defines it, and
`OpDecorate` may name a variable before its `OpVariable` line. The ID bound in the module
header covers both spellings, so names and numbers may be mixed in one module.

A name takes the next free number rather than a number chosen for it. To pin an exact ID,
write that ID as a number. The number a name received is not reported separately; it
follows from the rule above and can be read from the emitted module.

A name that is never defined anywhere in the module is rejected, and so is a name that is
defined twice; both report the line that caused them. The reference assembler `spirv-as`
instead allocates a number for a name it has never seen and leaves the resulting dangling
reference to the validator. Writing a name that is never defined is nearly always a
misspelling, so this assembler reports it where it was written.

## Fixed

- A rejected SPIR-V line was reported on the first SPIR-V line of the module rather than
  on the line that failed. The reported position is now the failing line, and a failure
  about a symbolic ID also names that ID.
- A trailing `;` after the last SPIR-V line was reported on the first SPIR-V line instead
  of the last.
