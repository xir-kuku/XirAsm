# XIRASM 0.3.3

Meta and DSL evaluation no longer repeats work it has already done, which makes
AArch64 sources assemble about twice as fast. Emitted bytes are unchanged.

## Parsed conditions are kept instead of re-parsed

A `meta_if` condition was parsed from its text on every execution, and the parse
was freed again afterwards. In a loop that runs once per instruction, the parse
cost more than evaluating the condition it produced.

The parsed form is now stored per condition and reused, so a condition is parsed
once no matter how many times its statement executes. Conditions are
context-independent at this stage, so one stored form stays correct under
different scopes; the text is copied in, which means a caller may pass a shorter
lived slice.

## Captured bindings are borrowed instead of copied again

`operand.eval` rebuilt its scope by cloning every binding captured with the
operand, on every call. The capture already owns a copy taken when it was made,
so the second copy was redundant: it walked every generated table again — one of
them holds 549 registers — each time an operand was evaluated.

Those bindings are now borrowed from the capture rather than copied. A capture
still means what it meant before: the values it was taken with, unaffected by
later changes to the module. Borrowed bindings are declared `const`, and every
path that could write to a binding refuses anything that is not `let`, so the
borrowed storage cannot be modified through them.

## Effect

On the 100,000-instruction AArch64 fixture, the lowering phase dropped from about
100 s to about 43 s, and the comparable x86-64 fixture is still about 385 times
faster because it does not go through the DSL layer at all. Every fixture,
including the tutorial and format outputs, assembles to identical bytes.
