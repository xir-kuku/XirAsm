# XIRASM 0.3.2

SPIR-V 模块的结果 ID 现在可以写名字，不必再手工编号；被拒绝的 SPIR-V 行也会报在出错的那一行上。

## SPIR-V 的结果 ID 可以写名字

SPIR-V 指令的结果 ID 可以写成名字：

```asm
spv.use()

OpCapability Shader
OpMemoryModel Logical GLSL450
OpEntryPoint GLCompute %main "main"
OpExecutionMode %main LocalSize 1 1 1
%void = OpTypeVoid
%fn_type = OpTypeFunction %void
%main = OpFunction %void None %fn_type
%entry = OpLabel
OpReturn
OpFunctionEnd
```

凡是能写数字 ID 的位置都能写名字：`=` 左边的结果 ID，以及所有引用 ID 的操作数。
名字由字母、数字和下划线组成，首字符不能是数字。

编号规则有两条：

- 数字 ID 保持写下的号不变，所以原本就写数字的模块，汇编结果与以前逐字节相同；
- 名字从 1 开始，按它在模块中**首次出现**的顺序编号，并跳过数字 ID 已经占用的号。

按首次出现编号，前向引用才能照直写：`OpEntryPoint` 可以先写入口点的名字，
定义它的 `OpFunction` 行在后面；`OpDecorate` 也可以先用变量名，`OpVariable` 行在后面。
模块头部的 ID 上界把两种写法一起算进去，因此同一个模块里名字和数字可以混用。

名字拿的是"下一个空号"，不是为它选定的号。要指定确切的 ID，就把它写成数字。
名字最终拿到几号不会单独回报，按上面的规则推算即可，也可以直接从产物里读。

整个模块里从未出现定义的名字会被拒绝，定义两次的名字同样会被拒绝，两者都报出出错的行。
参考汇编器 `spirv-as` 对从未见过的名字会直接分配一个号，把悬空引用留给校验器去发现。
写下一个从未定义过的名字，几乎都是拼错了，所以本汇编器在写下它的地方就报出来。

## 修复

- 被拒绝的 SPIR-V 行原先一律报在模块的第一条 SPIR-V 行上，而不是出错的那一行。
  现在报的是出错的行；如果问题出在符号 ID 上，诊断里还会给出这个名字。
- 最后一条 SPIR-V 行末尾多写的 `;`，原先报在第一条 SPIR-V 行上，现在报在最后一行。
